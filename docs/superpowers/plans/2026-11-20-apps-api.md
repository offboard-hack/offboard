# Apps API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose `@offboard/db` repositories as REST endpoints via Hono serverless functions deployed on Vercel.

**Architecture:** Single Hono app with route groups per domain. `createApp(repos: Repositories)` factory makes the app testable with PGlite. Entry file wires the real `DATABASE_URL` client. Vercel adapter via `@hono/vercel` `handle()`.

**Tech Stack:** Hono 4.13.19, `@hono/vercel` 1.0.1, `@offboard/db` (workspace), Vitest + PGlite for testing

**Spec:** `docs/superpowers/specs/2026-11-20-api-layer-design.md`

## Global Constraints

- Node >= 22.18.0
- Pinned exact versions (no carets) in `package.json`
- `verbatimModuleSyntax: true` in tsconfig
- 100% test coverage on new code
- CI workflow unchanged (no `.github/workflows` exists)
- Zero comments unless a linter demands it or a non-obvious constraint would be invisible
- `type: "module"` in package.json
- `@offboard/db` exports raw `.ts` — import it, typecheck with `noEmit`
- Vercel Node.js runtime (not Edge — `pg` needs TCP sockets)

## Review Focus

1. **Non-UUID path params** — `GET /offboardings/not-a-uuid` must return 404 (not 500 from Postgres). The repos already handle this via `isUuid()`, returning `null`; routes must translate `null` to 404. Test in Task 3.
2. **Missing request body or missing required fields** — `POST /offboardings` with `{}` or no body must return 400, not a Postgres constraint violation surfaced as 500. Test in Task 3.
3. **Invalid `?status=` query param** — `GET /equipment?status=bogus` must return 400, not pass a bad value to the repo. Test in Task 4.
4. **`POST /offboardings/bulk` with `[]`** — `createMany([])` returns `[]`; route should return 200 with `[]`. Test in Task 3.
5. **`POST /offboardings/:caseId/tasks` for nonexistent case** — FK violation from Postgres; route must catch and return 404. Test in Task 3.

### Task 2: Offboarding routes (list, get, create, createMany, delete)

**Files:**

- Create: `apps/api/src/routes/offboardings.ts`
- Create: `apps/api/src/routes/offboardings.test.ts`
- Modify: `apps/api/src/app.ts` (mount offboardings router)

**Interfaces:**

- Consumes: `createApp` from Task 1, `Repositories` type, `createTestDb`, `createRepositories`
- Consumes: `OffboardingRepository` — `list()`, `get(id)`, `create(input)`, `createMany(inputs)`, `delete(id)`
- Produces: Hono router at `offboardingsRoutes(repos: Repositories): Hono` mounted at `/offboardings`

- [ ] **Step 1: Create route file `apps/api/src/routes/offboardings.ts`**

Export `offboardingsRoutes(repos: Repositories): Hono` with:

- `GET /` → `repos.offboardings.list()` → 200 JSON
- `GET /:id` → `repos.offboardings.get(id)` → 200 JSON or 404
- `POST /` → validate body `{ name, role, department, deadline }` (all required strings) → `repos.offboardings.create(body)` → 201 JSON `{ id }`; on missing/invalid fields → 400
- `POST /bulk` → validate body is array of `{ name, role, department, deadline }` → `repos.offboardings.createMany(body)` → 200 JSON array; empty array → 200 `[]`
- `DELETE /:id` → `repos.offboardings.delete(id)` → 204 no content

- [ ] **Step 2: Mount in `app.ts`**

`app.route("/offboardings", offboardingsRoutes(repos))`

- [ ] **Step 3: Write tests in `apps/api/src/routes/offboardings.test.ts`**

Tests:

- `GET /offboardings` returns 200 and an array
- `POST /offboardings` with valid body returns 201 with `{ id }` (UUID)
- `POST /offboardings` with missing `name` returns 400
- `POST /offboardings` with empty body returns 400
- `GET /offboardings/:id` returns created case with tasks array
- `GET /offboardings/:id` with unknown UUID returns 404
- `GET /offboardings/not-a-uuid` returns 404
- `POST /offboardings/bulk` with 2 items returns 200 with 2 ids
- `POST /offboardings/bulk` with `[]` returns 200 with `[]`
- `DELETE /offboardings/:id` returns 204

### Task 3: Task routes (listByCase, create, updateStatus)

**Files:**

- Create: `apps/api/src/routes/tasks.ts`
- Create: `apps/api/src/routes/tasks.test.ts`
- Modify: `apps/api/src/app.ts` (mount tasks routes)

**Interfaces:**

- Consumes: `TaskRepository` — `listByCase(caseId)`, `create(caseId, input)`, `updateStatus(id, status)`
- Consumes: `OffboardingRepository.create()` — tests need a case to attach tasks to
- Produces: Two route groups: `/offboardings/:caseId/tasks` and `/tasks/:id/status`

- [ ] **Step 1: Create route file `apps/api/src/routes/tasks.ts`**

Export `taskRoutes(repos: Repositories): Hono` with:

- `GET /offboardings/:caseId/tasks` → `repos.tasks.listByCase(caseId)` → 200 JSON
- `POST /offboardings/:caseId/tasks` → validate body `{ title, team, status? }` → `repos.tasks.create(caseId, body)` → 201 JSON `{ id }`; catch FK violation → 404 (nonexistent case)
- `PATCH /tasks/:id/status` → validate body `{ status }` where status is `"done" | "inProgress" | "todo"` → `repos.tasks.updateStatus(id, body.status)` → 204

For the FK violation catch: wrap the `create` call in try/catch; a Postgres error with code `23503` (foreign key) maps to 404.

- [ ] **Step 2: Mount in `app.ts`**

Mount both route groups from the same function. The function returns a Hono app with both prefix groups, or the caller mounts them at the right paths.

- [ ] **Step 3: Write tests in `apps/api/src/routes/tasks.test.ts`**

Tests:

- `GET /offboardings/:caseId/tasks` for a case with tasks returns them ordered by position
- `POST /offboardings/:caseId/tasks` creates a task and returns 201
- `POST /offboardings/:caseId/tasks` with missing `title` returns 400
- `POST /offboardings/:caseId/tasks` for nonexistent case returns 404
- `PATCH /tasks/:id/status` with valid status returns 204
- `PATCH /tasks/:id/status` with invalid status returns 400
- `PATCH /tasks/not-a-uuid/status` returns 204 (repo no-ops on non-UUID)
